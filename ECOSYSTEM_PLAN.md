# EchoNext Framework Ecosystem Plan

## 🌟 Core Philosophy

**The current `echonext.go` is perfect - we build around it, not replace it.**

### Ecosystem Architecture

```
EchoNext Ecosystem
├── echonext (core)                 # ✅ Current package (unchanged)
├── echonext-cli                    # 🆕 CLI tool  
├── echonext-contrib               # 🆕 Optional extensions
├── echonext-examples              # 🆕 Project templates
└── echonext-docs                  # 🆕 Documentation
```

## 🏗️ 1. Core Package (github.com/abdussamadbello/echonext)

**Status: ✅ COMPLETE - Do NOT modify**

### What it does:
- Type-safe HTTP handlers
- Automatic request/response binding  
- OpenAPI 3.0 generation
- Swagger UI serving
- Validation with struct tags
- Standard Response[T] wrapper

### What it doesn't do:
- Database operations
- Configuration management
- Project structure enforcement
- CLI generation
- Testing utilities

## 🛠️ 2. CLI Tool (echonext-cli)

**Location: `cmd/echonext-cli/`**

### Commands:

```bash
# Project Management
echonext init <name>                    # Create new project
echonext version                        # Show version info
echonext help                           # Help system

# Code Generation  
echonext generate domain <name>         # Complete domain
echonext generate handler <name>        # HTTP handler
echonext generate service <name>        # Business service
echonext generate model <name>          # GORM model
echonext generate dto <name>            # Request/Response DTOs
echonext generate middleware <name>     # Custom middleware

# Database
echonext db init                        # Setup database config
echonext db migrate                     # Run migrations
echonext db seed                        # Seed data

# Development  
echonext dev                           # Hot reload server
echonext docs                          # Generate documentation
echonext test                          # Run tests with coverage
echonext build                         # Build for production
```

### Generated Project Structure (Multiple Executables Pattern):

```
myapp/                              # Generated by echonext init
├── cmd/                            # Multiple executables
│   ├── api/
│   │   └── main.go                # API server (echonext)
│   ├── worker/
│   │   └── main.go                # Background worker
│   ├── cli/
│   │   └── main.go                # CLI tool
│   └── migration/
│       └── main.go                # DB migrations
├── domain/                        # Business domains
│   ├── user/
│   │   ├── model.go              # GORM models
│   │   ├── service.go            # Business logic
│   │   ├── handler.go            # echonext handlers
│   │   ├── dto.go                # Request/Response types
│   │   └── service_test.go
│   └── [other domains]/
├── internal/
│   ├── config/
│   │   └── config.go             # Viper configuration
│   ├── database/
│   │   └── database.go           # GORM setup
│   └── server/
│       └── server.go             # echonext + middleware
├── tests/
│   ├── integration/              # API tests
│   ├── fixtures/                 # Test data
│   └── helpers/                  # Test utilities
├── configs/
│   ├── development.yaml
│   └── production.yaml
├── migrations/                   # SQL migrations
├── docker-compose.yml
├── Dockerfile.api               # API server image
├── Dockerfile.worker            # Worker image
├── Makefile
└── go.mod
```

### Build Commands:

```bash
# Build all executables
make build                      # Builds all to ./bin/

# Build specific executables
go build -o ./bin/api ./cmd/api
go build -o ./bin/worker ./cmd/worker
go build -o ./bin/cli ./cmd/cli
go build -o ./bin/migration ./cmd/migration
```

### Deployment:

```yaml
# docker-compose.yml
services:
  api:
    build: 
      context: .
      dockerfile: Dockerfile.api
    command: ./api
    ports: ["8080:8080"]
    
  worker:
    build: 
      context: .
      dockerfile: Dockerfile.worker
    command: ./worker
    
  migration:
    build: .
    command: ./migration up
```

## 📦 3. Contrib Packages (echonext-contrib)

**Location: `pkg/contrib/` or separate repositories**

### Database Package (`echonext-contrib/database`)

```go
// Optional GORM integration helpers
package database

import (
    "gorm.io/gorm"
    "github.com/abdussamadbello/echonext"
)

// Connection management
func Connect(cfg DatabaseConfig) (*gorm.DB, error)
func WithRetry(db *gorm.DB) *gorm.DB

// Repository patterns (optional)
type Repository[T any] interface {
    Find(id any) (*T, error)
    Create(entity *T) error
    // ... CRUD operations
}

// Base repository with generics
type BaseRepository[T any] struct {
    db *gorm.DB
}

// Transaction helper
func WithTx(db *gorm.DB, fn func(*gorm.DB) error) error
```

### Config Package (`echonext-contrib/config`)

```go
// Optional Viper helpers
package config

import "github.com/spf13/viper"

// Standard config structures
type AppConfig struct {
    Name string `mapstructure:"name"`
    Port int    `mapstructure:"port"`
}

type DatabaseConfig struct {
    Driver string `mapstructure:"driver"`
    DSN    string `mapstructure:"dsn"`
}

// Loading helpers
func Load[T any](target *T) error
func LoadWithEnv[T any](prefix string, target *T) error
func Watch[T any](target *T, callback func(*T)) error
```

### Testing Package (`echonext-contrib/testing`)

```go
// API testing utilities
package testing

import "github.com/abdussamadbello/echonext"

type APIClient struct {
    app   *echonext.App
    token string
}

func NewAPIClient(app *echonext.App) *APIClient
func (c *APIClient) GET(path string) *Response
func (c *APIClient) POST(path string, body interface{}) *Response
func (c *APIClient) WithAuth(token string) *APIClient

// Test fixtures
type FixtureManager struct {
    db *gorm.DB
}

func (f *FixtureManager) LoadUsers(users ...User)
func (f *FixtureManager) LoadProducts(products ...Product)
func (f *FixtureManager) Clear()

// Test suite base
type Suite struct {
    App    *echonext.App
    DB     *gorm.DB
    Client *APIClient
}
```

## 🔧 Technical Decisions

### Repository Structure:
```
echonext/               # Core package (current)
├── cmd/echonext-cli/   # CLI tool
├── pkg/contrib/        # Optional packages
├── examples/           # Example projects
└── docs/              # Documentation
```

### Versioning:
- Core follows semantic versioning
- CLI versioned independently
- Contrib packages follow core version
- Examples use latest stable

### Dependencies:
- Core: Minimal (Echo, OpenAPI, validator)
- CLI: cobra, text/template, embed
- Contrib: Optional per package
- No forced dependencies

### Backward Compatibility:
- Core API: Never break
- CLI: Deprecation warnings
- Contrib: Major version bumps
- Examples: Always latest patterns

## 🎯 Key Principles

1. **Extend, Don't Replace** - Core package stays unchanged
2. **Optional Everything** - All contrib packages are optional
3. **Multiple Executables** - Standard Go pattern for scalable apps
4. **Zero Lock-in** - Can remove framework anytime
5. **Community First** - Examples and documentation drive adoption
